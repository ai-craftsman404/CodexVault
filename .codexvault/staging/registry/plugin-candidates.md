# Plugin Candidates

Track plugin ideas before they enter the factory process.

| Candidate | Status | Target User | Purpose | Next Step |
| --- | --- | --- | --- | --- |
| orchex | designing | Engineers and teams using Codex for governed implementation work | Enforce deterministic staged workflows, artifacts, gates, and stack-aware execution profiles | Finalize V1 scope, acceptance criteria, and pre-build research notes |
| codexvault | researching | Developers and Codex users who need workspace resilience and recovery | Capture normalized workspace state, create portable snapshots, and guide safe restore and validation flows | Finalize scope boundaries, security assumptions, and test matrix before build |
| premortemx | ready-for-release | Release decision-makers, developers, and leads who need evidence-backed pre-release risk analysis | Turn pre-mortem reasoning into an auditable release-gating workflow with adaptive guardrails and local learning artifacts | Final official-doc verification and live Codex discovery check before public release |
| codex-last-mile-verifier | testing | Internal Codex plugin builders, skill builders, and extension maintainers | Standardize real Codex discovery, install, and smoke-test verification with reusable evidence and pass/fail reporting | Run live verification against sample plugins and skills |

## Status Values

- `idea`
- `researching`
- `designing`
- `building`
- `testing`
- `ready-for-release`
- `released`
- `deferred`
- `rejected`
